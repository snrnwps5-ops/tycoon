# 자동 테스트 (헤드리스 Chrome)

게임을 고친 뒤 **배포 전에 한 번** 돌려 주세요. 3D(`tech.html`)와 2D(`tech-test.html`)를 실제로 띄워서 핵심 흐름이 깨졌는지 확인합니다.

```bash
cd tests
npm install          # puppeteer-core, three@0.128 (오프라인 실행용)
npm test             # 전체 (약 8분)
npm run test:3d      # 3D만
node run.js --grep 매니저   # 이름에 '매니저'가 들어간 테스트만
CHROME=/경로/chrome npm test # Chrome 위치가 다를 때
```

- 결과는 `✅ PASS` / `❌ FAIL`과 실패 이유로 나옵니다. 하나라도 실패하면 종료 코드 1.
- 캡처는 `tests/shots/`에 남습니다(저장소에는 올라가지 않음).
- 게임 안 훅: `tech.html`을 `file://`로 열거나 `?test=1`을 붙이면 `window.__T`가 생깁니다(영업 매출·민원 조작, 결과창 열기 등). 실제 사이트(https)에서는 생기지 않습니다.

## 테스트 목록

| 파일 | 확인하는 것 |
|---|---|
| `a_sync2d` | `index.html` = `tech.html`, `version.txt`와 두 페이지의 `var V`가 같은 숫자, v2.34 이후 함수가 2D 판에도 있는지 |
| `b_smoke` | 영업 시작 → 실패/클리어 판정 → **결과창 첫 화면에 다음 날 버튼**, 상세 접기, 본사 총평 위치, 페이지 오류 0 |
| `c_loop` | 러시 챌린지 등장·보상, 도감 등록, 연승 증가·실패 시 초기화, 보상 상자 |
| `d_gate` | 별이 모자라면 게이트 창, 다시 도전 → 원래 진행 복귀, 별을 채우면 다음 매장 |
| `e_hq` | 본사 추천 요건 창, AI 판정 미달 보류·통과 임용, T.O. 소진 후 스카우트 제외 (3D만) |
| `f_nav` | 서울·인천·본사 바닥 전체에서 손님이 나갈 수 있는지 (3D만) |
| `g_mgr` | 직원 외형 다양성, 매니저 업무(코칭·진정), 본사 AI→매니저·매니저→직원 평가, 매니저 승진 |

- 새 흐름은 `x_이름.test.js`로 추가하세요. 형식은 기존 파일과 같습니다(`module.exports={name, modes, run}`).
